# ToolBox Liquid Glass 光学升级计划

> 参考基线：Sillage `ec37dd0790f537d51ae27071d051c8d38a33c7ce`；计划目标版本：ToolBox 0.5.0。
> 0.4.1 先交付一级页签闪烁修正和小工具版本确认，本计划不与这些稳定性改动混成一次高风险材质替换。

## 1. 参考结论

Sillage 值得参考的是玻璃层的组织方式，而不是直接照搬它的页面外观：

- 玻璃效果由亮度增强、轻量模糊、边缘折射和中性染色组成，按压时主要改变折射与几何反馈。
- 顶栏把材质层与标题、按钮内容分开，底边使用由实到透明的渐隐遮罩，使内容可以自然滚入顶栏下方。
- 背景采集层独立且稳定；悬浮输入区等玻璃组件放在采集层外，避免组件采到自己。
- 提供开发调试预览来比较明暗背景与参数，但普通用户只看到“降低透明度”等有意义的选择。

## 2. 产品边界

### 采用

- 顶栏和底栏采用稳定的共享背景源，材质层与文字、图标分层绘制。
- 底部选中项使用很轻的透镜位移、边缘高光和按压回弹；未选中项保持清楚、安静。
- 一级顶栏允许使用渐隐下缘，让滚动内容与白色状态栏连续过渡。
- 加号等局部主操作可以使用独立玻璃圆形，但命中区域仍至少 48dp。
- 明暗模式使用中性玻璃染色，系统取色只用于选中、焦点和有语义的操作。

### 不采用

- 不把工具卡片、列表行、输入区、弹层正文或状态标签改成玻璃。
- 不在玻璃内再嵌套玻璃，不为“果味”加入大面积壁纸或彩色光斑。
- 不向普通用户开放模糊半径、折射量、色散等工程参数。
- 不采集、截图、移动、缩放或淡化 WebView；运行顶栏继续使用同几何的清晰实底。
- 不恢复一级页面整体交叉淡入。页面切换即时完成，动效只发生在底栏选中反馈内部。

## 3. 技术方案

继续使用现有 `ThemeStyle`、DataStore、`SettingsViewModel` 与 `ToolBoxTheme`，不复制业务页面，
不改 `.tbx`、权限、JS API 或数据库结构。

1. 在 `core-ui` 的 `ToolBoxGlassState` 内增加材质后端与效果档位，业务层只使用 ToolBox token 和组件。
2. Haze 1.7.3 保持默认实现和稳定回退。建立独立样板比较 Haze 与固定版本 Kyant Backdrop 2.0.0，
   验证通过后才决定是否把 Kyant 用于底栏选中透镜和局部按钮。
3. 一级页面的顶栏、内容与底栏共享一个长期存在的背景源；路由内容切换不销毁背景源，也不暂停后再
   预热材质。顶栏文字与底栏图标始终画在效果层上方。
4. `reduceTransparency`、系统关闭动画、页面被覆盖、硬件加速不可用或效果异常时，停止实时采样与
   折射，使用相同颜色和边框的实底。回退不改变尺寸、位置或可操作性。
5. 底栏两个目的地各占一半可用宽度，图标与文字作为一个整体在各自区域的水平、纵向中心；大字体
   达到既有阈值时转为仅图标，但保留 TalkBack 标签。
6. 运行页保持现有实底顶栏，不接入任何背景采集后端；工具 HTML 与宿主材质互不影响。

Kyant 只作为候选，因为其多背景源、图层卸载和部分设备渲染仍有
[公开问题](https://github.com/Kyant0/AndroidLiquidGlass/issues/100)；另有
[图层解绑需求](https://github.com/Kyant0/AndroidLiquidGlass/issues/60)。样板失败时继续使用
Haze，仅吸收渐隐顶栏、局部按压反馈和材质分层，不阻塞 0.5.0 的视觉升级。

## 4. 实施阶段与退出条件

| 阶段 | 交付 | 退出条件 | 可回退点 |
|---|---|---|---|
| P0：0.4.1 稳定基线 | 取消一级页整页 alpha；同版本覆盖和降级改为确认后原子替换；版本、CI 与手动验收同步 | 顶栏颜色连续、无双标题；取消安装不写入，确认后内容生效，失败或中断恢复原包 | `NavTransitions.None` 与更高版本直接安装为稳定基线 |
| P1：材质实验台 | `core-ui` debug 预览，固定列表、纯色、图片三种背景，比较 Haze 与 Kyant | 浅深色、按压、滚动、降低透明度均可观测；记录 GPU/帧时间与异常设备 | 删除候选后端，不影响业务页 |
| P2：持久主框架 | 一级顶栏、内容、底栏共享一个常驻背景源，材质与内容分层 | 连续切换 20 次不重建导航/ViewModel，不出现采集预热闪烁 | 继续使用 Haze 与实底 |
| P3：光学细化 | 底栏选中透镜、按压反馈、顶栏渐隐下缘、局部圆形主操作 | 反馈不改变布局；关闭动画和降低透明度时立即成为稳定实底 | 每项效果有独立 token，可逐项关闭 |
| P4：全页适配 | 工具、设置、外观、详情、权限、后台、帮助与弹层统一检查 | 内容层保持清晰；二级导航、权限操作和 WebView 生命周期无回归 | 页面继续使用同一 ToolBox 组件出口 |
| P5：发布 0.5.0 | CI、优化 APK、签名、哈希、回执与真机验收记录 | 所有门禁通过，签名连续；真机已完成规定矩阵后再声明流畅度 | 0.4.1 可随时作为稳定版本 |

## 5. 验证矩阵

### 自动检查

- 保留设置持久化、主题切换不重建 AndroidView、对比度和完整导航旅程测试。
- 为材质后端选择增加纯 Kotlin/Compose 状态测试：正常、降低透明度、关闭动画、覆盖和无硬件加速。
- 检查两种主题、浅深色与系统取色下的正文、图标、边框和实底回退对比度。
- CI 编译 production 与 instrumentation 源，执行既有最小测试入口、安全检查、R8、签名和资源一致性检查。
- 不增加截图或 golden 门禁。

### 手动与真机

- API 33、35 和当时最新稳定 API；至少一台 HyperOS 真机，手势与三键导航各一次。
- 工具 ↔ 设置连续切换 20 次，录屏逐帧确认顶栏无灰闪、无双标题、底栏选中反馈不移动布局。
- 正常、降低透明度、系统关闭动画、浅深色切换、2 倍字体、窄屏、横屏和 TalkBack。
- 有运行会话和 WebView 输入时换肤，确认页面、输入、通知、权限弹层和返回栈都保留。
- 分别采集 Haze、候选折射和实底模式的帧时间、GPU 渲染与内存；以同设备 0.4.1 为基线，先记录数据，
  再决定 0.5.0 的接受阈值，不用模拟器结果代替真机结论。

## 6. 发布策略

- `0.4.1 (14)`：包含已定位的页签闪烁修正、同版本/降级确认和相应文档/CI 版本同步，作为可回退稳定点。
- `0.5.0`：从 P1 样板开始单独开发；材质后端先受内部开发开关控制，选型完成后才成为正式效果。
- 分支交付时分别列出 CI 已通过项、模拟器观察和真机待验收项。没有真机数据时不宣称 120Hz、
  帧率、功耗或 OEM 稳定性达标。
