# 安全存储开关与 NextFlux 启动

当前修复版本：ToolBox 0.8.30 / 63，NextFlux 1.0.36 / 57。NextFlux 使用的原生接口未变化，最低宿主仍为 0.8.29；安全存储确认框修复由 0.8.30 提供，适用于所有声明 `storage.secure` 的工具。

## 安全存储确认

权限中心允许关闭安全存储。关闭前需要显示“关闭并清除安全存储？”并由用户明确确认；取消不修改授权，确认后才进入原有撤权、清除密文和密钥的流程。

原确认框在 `ToolBoxAppScaffold` 外创建。Miuix Scaffold 提供弹窗状态容器，外部的 OverlayDialog 没有被该容器渲染。点击把确认状态设为 true，但界面不显示，授权保持开启。这是宿主共用权限界面的问题，与某个 TBX 的声明或用户是否开启权限无关。

确认框移入该 Scaffold 的内容树。开关、授权写入与清除流程沿用当前实现，不增加绕过确认的路径。

## NextFlux 启动和保存

启动阶段依次是连接 ToolBox、恢复设置、恢复登录信息、恢复阅读缓存（存在有效账号时）、打开阅读界面。同步与后台模块的 flush 导入等待偏好初始化；早期退出也使用同一个初始化 Promise。

错误页显示失败阶段与允许列出的原生错误码或标准错误类型。只有 `PERMISSION_DENIED` 才提示工具授权；系统权限、能力不匹配、存储额度和阅读缓存有各自的说明。其余失败保留现有数据并给出重试入口。认证恢复保留原生错误码和 cause；页面不显示原生错误正文、堆栈、账号或密钥。

真实开发入口验证已证明已保存的设置和 AI / 语音密钥能够恢复，没有复现设置丢失。完整偏好数据仍出现一次无值变化的普通存储写入：恢复设置把密钥字段放在 JSON 尾部，store 挂载按当前默认字段顺序重新编码，字符串顺序变化触发了保存。

设置为平坦 JSON 值，持久化引擎在字符串变化时比较字段和值；仅改变字段顺序时更新内存编码而不发原生写入。实际值变化仍进入原有串行写入队列：先保存有变化的安全密钥，再保存不含密钥的普通设置，flush 等待实际写入结果。

## 验证范围

全部构建与运行验证在 GitHub 执行。本地只检查源文件、语法、元数据和差异。

- Android：仅权限中心真实触摸回归，覆盖两种现行主题、行与滑块触摸、确认前不修改授权、取消、确认及忙碌状态。
- NextFlux 开发入口：仅三个启动用例；页面、路由、store、偏好引擎全部使用真实实现，只在 ToolBox 原生 API 边界提供固定测试数据与错误。验证恢复、启动零写入、随后实际设置和密钥保存，以及两类原生读取失败。
- NextFlux 生产打包入口：仅未登录和已登录两例，通过实际 Vite 构建的入口及拆分模块打开页面。已登录例使用 1.0.34 的 v3 空缓存根结构和真实缓存 Worker，原生网络边界明确拒绝请求，检查本地页面仍可打开；不代表已经验证用户设备上的非空历史缓存。
- 原有权限清除、媒体、同步、缓存和调试检查未因本次问题全量重跑；相关生产实现未变的证据继续保留。

用户确认 1.0.34 可以使用。将入口、认证和偏好源文件保持为 1.0.35 的原实现，云端生产启动测试的未登录和已登录两例均无法进入页面；开发入口结果不能代替打包入口证据。修复后复跑相同生产入口用例。

用户提供的启动截图只有原先的泛化提示，无法据此断定设备上的具体异常。若升级后仍无法启动，新的失败阶段和错误码是下一步定位的依据；不通过清除用户数据掩盖读取错误。
