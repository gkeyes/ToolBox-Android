# ADR 0001：可选签名的内部验证，不建立发布者信任流程

- 状态：Accepted（取代 2026-08-28 的同名审核/信任决定）
- 日期：2026-08-30

## 背景

ToolBox 是个人本地小工具宿主。原方案把签名状态、未知发布者和可信发布者库暴露为安装审核，
这制造了无助于用户完成导入的步骤。与此同时，`AGENTS.md` 的安全不变量仍要求无效签名
阻断，完整性与 ZIP 边界也不能放松。

## 决策

1. `.tbx` 没有 `signature.json` 时可正常导入；UI 不显示“未签名”、发布者、风险或信任徽标。
2. 包存在 `integrity.json` 时必须验证文件集合和 SHA-256 覆盖。
3. 包存在 `signature.json` 时，使用包内 Ed25519 public key 对 `integrity.json` 原始字节验证；
   public key/key ID/格式/签名任一无效都阻止安装。
4. 不持久化 publisher、key continuity、信任状态、指纹、审计记录或用户级“信任此发布者”决定。
5. 验证在内部检查阶段完成；用户只收到成功或可操作失败消息。失败不创建安装记录或文件残留。

## 后果

- 保留“无效签名阻断”不变量，也保留 integrity 防篡改能力。
- 移除发布者信任库、签名状态界面、未签名严格策略、审核会话和关联测试。
- 签名只是一项可选包完整性机制，不是 ToolBox 的用户体验或权限授权来源。

## 验证

在 `TESTING.md` 的导入参数化矩阵中覆盖：无签名有效包、有效 integrity、完整性篡改、
有效签名、错误 public key/key ID、原始 integrity 字节变化、无效签名。预期无签名/有效签名
均安装；其余失败且没有目录、事务或数据库残留。
