# 备份与恢复

入口：设置 → 备份与恢复。宿主原生 Compose 页面，不改小工具 HTML、`.tbx`、JS API 或 Room schema。

## 使用

导出时先确认一次敏感数据提示，再生成和复核备份，最后通过系统文件选择器选择本地保存位置。恢复时选择 ZIP，等完整校验结束，核对宿主设置覆盖、工具旧/新版本、冲突数、跳过内容和运行任务提示，再确认恢复。重复恢复、同版本覆盖和降级仍走现有安装器。

ZIP 未加密，可能包含账号、密码、token 和应用数据。ToolBox 没有新增网络上传或同步逻辑；文件选择器请求 `EXTRA_LOCAL_ONLY`，应选择本地存储提供器。

## 格式 v1

```
manifest.json
checksums.json
host/settings.json
tools/<tool-id>/package.tbx
tools/<tool-id>/metadata.json
tools/<tool-id>/data/kv/<sha256(key)>.json
tools/<tool-id>/data/secure.json       # 仅能解密并迁移时存在
tools/<tool-id>/data/tasks/<sha256(task-id)>.json
extensions/                          # 未来扩展；当前报告但不应用
```

根清单含格式标识 `io.toolbox.backup`、格式版本、最低读取器版本、应用版本、时间、工具 ID/版本及逐文件大小/SHA-256。checksums 包含所有负载和 manifest 的散列，不散列自身，避免循环定义。SHA-256 用于损坏检测，不宣称提供发布者认证或抵御攻击者整体重签归档。

工具 KV 是当前 ToolBox 配置、storage 与持久化文件内容的实际存储位置，按现有行与 chunk 完整导出。metadata 保留安装时间、展示信息和授权历史；授权历史不直接恢复。后台任务及结果保留为完成/停止历史，不作为待执行请求重新入队。

未知普通字段跳过并报告；未来主格式拒绝导入；未来工具数据版本跳过整个工具，避免覆盖后丢失未知数据。未知扩展仍保留在用户原归档中。

## 一致性与回滚

使用现有仓库和 DataStore，增加共同写入边界，不复制正在使用的 SQLite/WAL。导出在一致性事务下获取工具目录与 KV，恢复先暂停后台工作和运行会话，再创建私有回滚日志；正常安装器发布工具目录，Room 更新与 DataStore 更新由持久补偿日志协调。成功标记、目录切换与日志回收采用原子重命名及 fsync。失败使用旧目录与逻辑数据库快照回滚；进程重启在开放宿主数据前继续恢复。回滚失败时禁止新写入并提示释放空间后重启，不应卸载/清除应用数据。

私有 ZIP 使用 `.partial` + 原子发布。SAF 的任意 DocumentsProvider 不统一提供原子替换接口，因此目标文件采用完整写入、重新读取散列验证、失败/取消删除。强制结束进程或提供器拒绝删除仍可能留下不完整文件，页面会说明限制；不能把这一层描述为对所有提供器的原子替换保证。

## 明确边界

Android Keystore 硬件密钥不导出。能够解密的安全存储以数据形式迁移，再由目标设备密钥重新加密；无法迁移时原加密记录仍在归档中，并保留目标设备原安全数据，提示重新登录。恢复前仍检查当前工具 manifest 和 ToolBox 授权，Android 系统权限需按系统流程取得。

不复制 WebView 私有浏览器数据库、硬件密钥、活动 JS 堆/会话、系统闹钟或系统授予的外部文件 URI 权限。标准 ToolBox API 的 storage/secure 数据已覆盖；只保存在 WebView cookie/localStorage/IndexedDB 的状态需要重新登录或重新生成。恢复会明确停止全部当前工具会话与后台任务；即使取消或回滚，已停止的会话也需用户重新打开，不能伪造原执行进度。

默认安全上限：压缩文件 2 GiB、展开总量低于 4 GiB、单条目 256 MiB、60,000 条目、路径 240 字符、最大压缩比 500。工具包仍受原 `.tbx` 更严格限制。安全存储可迁移 JSON 32 MiB；超出时报告仅归档原加密记录。大备份需要归档、展开内容和回滚快照同时占用私有存储，空间不足会失败并清理临时文件。

## 验证

```
./gradlew --no-daemon verifySecurityInvariants :tool-api:verifyToolBoxApiContract \
  :app:assembleDebug :app:compileDebugAndroidTestKotlin \
  :app:testDebugUnitTest :core-data:testDebugUnitTest :tool-package:testDebugUnitTest
./gradlew --no-daemon :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=io.toolbox.host.backup.HostBackupServiceTest,io.toolbox.host.backup.BackupScreenTest
```

单元测试覆盖 ZIP 往返、恶意归档、校验、版本、写入锁、取消、崩溃回滚及 ViewModel 状态；行为测试使用隔离目录中的真实 Room/DataStore/安装器/Keystore，并检查设置入口和 SAF Intent。CI 的 API 35 模拟器行为测试不等于 HyperOS 或实体手机验证；没有恢复截图/golden 门禁。

真机验证：先保留独立原始备份，安装开发分支的兼容签名构建。设置主题、系统取色、透明度及后台选项，为两个工具保存普通和安全配置，导出；修改配置/升级工具后导入，检查覆盖预览和任务提示。再检查同版本重复恢复、未安装工具重装、取消选择/恢复、损坏文件、剩余空间不足及重新登录提示。不要在未验证前删除原备份。
