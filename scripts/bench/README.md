# ToolBox 和 NextFlux 的性能复测

## NextFlux 搜索

准备旧版和新版各自的生产构建目录，安装 NextFlux 浏览器测试依赖和 Chromium。在仓库根目录运行，两个目录按旧版、新版顺序传入，也可用 `--chromium` 指定本地浏览器。

```sh
node scripts/bench/nextflux-search.mjs /path/to/old/dist /path/to/new/dist --rounds=50
```

程序在本地打开两个独立的浏览器上下文，为每版准备同一批 200 篇文章，轮流查询两组中文关键词。先预热一轮，再交替测试顺序。每轮从输入事件计时，到第一条正确结果布局可见后的下一帧。输出包含每轮耗时、中位数、P95 和 Chromium 版本。宿主存储与网络使用现有测试夹具。

## Android 宿主冷启动

在同一台手机上对比旧、新 APK。先保存当前工作并结束工具后台任务。每轮会强制停止 ToolBox，然后打开首页。保持屏幕解锁、相同折叠状态、刷新率、系统 WebView 和工具集合，前后两次分别指定新输出文件。

```sh
python3 scripts/bench/android-startup.py --cold --rounds 20 --output old-outer.json
```

脚本记录 Android 的启动耗时和宿主报告首页就绪的完全绘制时间。系统日志缺少相应标记时，该轮完全绘制时间记为空。内屏、外屏分开测试。脚本已用合成的 ADB 返回值验证解析，实际性能数据须在设备上取得。

### 同模拟器覆盖升级对照

在 `host-comparison.json` 指定有已签名构建产物的两次 main 提交。更改该文件会在同一台 API 35 模拟器上先测基准，再覆盖安装候选版。两组各测 20 次强制停止后的启动，以及到达首页后的宿主 PSS。原始数据在工作流的 host-cold-start-comparison 附件。手动运行时可换用仍在 Actions 保留期内的构建 SHA。模拟器冷启动时间与首页 PSS 单独列示，折叠屏的同步、连续阅读和渲染进程仍需实机采样。

### 实机阅读、同步与熄屏采样

打开同一篇缓存长文或准备好同一批增量数据。运行 `python3 scripts/bench/android-flow.py read --seconds 30 --output old-read-01`，见到开始提示后执行固定操作。同步使用 `sync`。分别指定内外屏、旧新版的新目录。脚本保存每个进程的原始 PSS 采样、可访问的 CPU tick、帧记录及系统与 WebView 版本。已从开发者工具核实归属的渲染进程用 `--renderer-pid PID` 加入。缺少渲染进程、进程重启、读取受限或工作量不同的样本需单列。峰值是按间隔采集的近似值，CPU 时间为 tick 差除以设备的时钟频率。

熄屏场景使用 `background --seconds 14400`。固定用户配置的半小时同步，在同一网络和供电条件下重复三轮。脚本只在两端采样电源状态和电池统计，中间不轮询手机。用 NextFlux 的同步时间、未读变化与通知记录核对计划轮次。系统采样本身无法证明每轮同步成功。
